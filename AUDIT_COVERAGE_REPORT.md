# SGLang KV-cache memory-safety audit — coverage report
2026-10-16. Scope: production disaggregated deployments (prefill/decode split; Mooncake multi-NIC RDMA + NIXL on K3), page-size 64, fp8_e4m3/bf16 KV, chunked prefill 12-32k, HiCache (write_through, page_first_direct, direct IO, Mooncake store with group semantics), SWA, hybrid mamba/linear (K3), DSA (DSv4), EAGLE/DSPARK spec decoding, multimodal, DP attention, cache-report. Out of scope: hf3fs/nixl-file/npu/simm/lmcache/flexkv/eic storage backends; non-disaggregated-only paths (audited opportunistically where production-adjacent).

## Executive summary
The audit found **17+ confirmed memory-safety bugs**, **every one fixed on `main` (via dev) with CPU-runnable regression tests**, plus **borderline-hardening fixes**, and a **complete per-tag hotfix kit** (~17 families × up to 5 production versions, git-apply-verified) shipped under `hotfix/`. The highest-frequency pattern across families: **shared-state ownership gaps between the radix/tree and the movement threads** (transfer engine, offload manager, prefetch io thread) — freeing or overwriting device/host/HELLO slots while a transfer, prefetch continuation, or drain is still outstanding. Every such path is now closed by hold-until-drained, exact-byte accounting, ownership-checked frees, or locked staging.

Verification discipline: every confirmed bug had an independent reproducer or at least one independent verifier; every 'clean' verdict had a challenger who actively tried to break it (multiple verdicts were reversed in both directions this way); race claims required a concrete thread interleaving at specific lines. Version triage checked every confirmed bug against v0.5.14, v0.5.15.post1, v0.5.16 (K3-base proxy — the vendor K3 SHAs 87dd4596/bd4828e2 are not publicly fetchable; K3-specific files are flagged), v0.5.17, v0.5.20, and HEAD.

## Top findings (ranked by fleet impact)
1. **Prefill→decode KV can be freed/finished while the RDMA transfer is still outstanding, then reused by a later request — silent cross-request corruption.** Two shapes:
   - *Device path (NIXL device transfer + Mooncake first-failure-return)*: deferred-release machinery missing entirely before v0.5.20-ish; the only sync was a 30s wall-clock timeout ('free after timeout regardless'), and a one-shot abort-notification map could swallow the signal. Fixed: device-side deferred release now holds until ack-by-peer-drained or peer declared dead, with the abort map made sticky (F9) and completion wired to both protocol and device paths (V4 chain, board #19/#44/#31).
   - *SWA-offload retract*: retracting a request with pSwas offload transfers in flight freed device rows under a live D2H, persisting wrong KV under correct hashes. LIVE in every production tag. Fixed at main by drain-before-retraction + bounded wait + caller-side catch for the wedge case (boards V8/#52, hotfix CLASS-5 ×5 tags).
2. **RadixCache.checkpoint can shrink cache_protected_len and free pages the tree still owns** (UAF family; any later turn reusing the freed pages corrupts another request's tree). Trigger reachable at decode startup (bootstrapped radix on decode side per chunked prefill), chunked-prefill queue-collision with stale lock-pin accounting, and retract-rest-caching under page-alignment invariants. All production versions. Fixed (#38) with page-boundary clamp + assert; regression test fails pre-fix with the exact upstream assert.
3. **Mamba deferred copy-on-write: the source state could be evicted/cloned from a slot that had been freed and reissued** (use-after-evict; cross-request state pollution on Kimi K3 hybrid mamba + spec-decoding stacks with mamba COW at host-cache resume time). Head fix: lock ALL components during the stage→collect window + catch-all path fix (board #17, MR #52 on dev); per-tag hotfix F-1 ×5 with a backport README (the .14 variant needs an added pool-free clear site — flagged).
4. **Mooncake store short reads treated as success, at four sites**: batch KV get, single KV get, prefetch `_batch_postprocess`, embedding `batch_get`. A 1-byte read of a 1MB page or standard validators that compare only `>0`/`>=0` marked a torn or truncated read as a valid page → stale/garbage/cross-request KV served under correct hashes. ALL production versions, including the multi-tenant shared-store topology (we evaluated the shared-store blurring case explicitly). Fixed on dev (exact-byte predicate, board #33 + embedding side via radix-emb); hotfix MC-SHORTREAD ×5 tags + embedding family.
5. **EAGLE/DSPARK draft-KV pointer mixup for multi-layer draft on non-MLA models**: modulo-divisibility detection misidentified the draft branch pointer set; the draft model's K-cache reads pointed at the wrong layer physical pages silently (F15). Fixed with explicit model-config layer counts (#30 merged 9fa4981e26); hotfix F15 ×4 tags.
6. **Host-pool free() double-free + −1 sentinel wrap + stale-free**: free() accepted duplicate frees and negative indices silently across MambaPoolHost, DeepSeekV4PagedHostPool and LogicalHostPool; unified-pool F0 admitted a stale free of an entry that did not belong to the freeing generation. All versions. Fixed (free-guards, generation-checked frees, debug freed-set sweep on device pools; boards #25, #40, hotfix H-FREEGUARDS ×5).
7. **Unified cache: checkpoint_into_tree/finish-trim could compute an insert length <= cache_protected_len and call free() on the tree-owned region** (HEAD-only class, sibling of #2; caught by the challenger protocol after an initial NOT-VULNERABLE verdict was reversed). Fixed (#59).
8. **TP rank divergence on mamba sidecar prefetch hits** (hi_mamba legacy path, v0.5.14–v0.5.17 + K3): completed_tokens MIN-reduced across TP but the mamba host-slot attach/free read rank-local extra_pool_hit_pages → divergent host trees and freed slot reissued while tree-referenced. Refuted at HEAD/.20 (the reduce exists there since the hybrid rewrite — verified by four independent traces after a public challenge); fleet hotfix C4-MAMBA-MIN ×4 tags.
9. **Wire-trust-boundary**: negative `chunk_idx` and non-positive `pages_per_chunk` on the disaggregation staging/control wire could alias chunk indices across concurrent transfers and regress the ring head — cross-request transfer redirect (F20/F21). Fixed with strict wire-field validation at the codec (boards #54/#44; covers both the NIXL AUX_DATA bounds union and the Mooncake wire).
10. **Info-leak / exposure class (read-only)**: ragged EAGLE/DSPARK verify with COMPACT + variable per-request lens reads stale cross-request KV from the tail padding fold (R-1); speculative DRAFT over-empty-pool asserts observed during scale-out (F-4 family); embedding TOCTOU unpin could steal a pin owned by another request (v0.5.20+ board #18).
